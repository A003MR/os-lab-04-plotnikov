# Задание 5. Пароль на виду

## Что мутили
Запустили фейковый процесс, имитирующий утилиту базы данных с паролем в аргументах (`exec -a`). Переключились на пользователя `student2` и с помощью `ps aux | grep -- --password` увидели пароль `SuperSecret123` чужого процесса. 
При попытке прочитать `environ` (переменные окружения) того же процесса получили отказ в доступе (`Permission denied`).

## Отвечаем на вопросы
**Почему cmdline доступен всем, а environ — нет?**
Командная строка (`/proc/PID/cmdline`) намеренно открыта для чтения всем пользователям. Это сделано для удобства администрирования: чтобы админ мог через `ps` увидеть, какие процессы запущены и с какими аргументами. 
А переменные окружения (`/proc/PID/environ`) содержат потенциально чувствительные данные (токены, ключи), поэтому ядро защищает их по UID — читать их может только сам владелец процесса или `root`.

**Как правильно передавать пароль программе и почему не аргументом?**
Правильные способы:
1.  **Интерактивный ввод** (программа сама спросит пароль и скроет его ввод).
2.  **Файл конфигурации** с правами доступа `600` (читать может только владелец).
3.  **Переменная окружения** или через `stdin`.
**Почему не аргументом:** потому что аргументы командной строки видны абсолютно всем пользователям системы через `ps`. Любой юзер на сервере сможет украсть пароль к базе данных, просто запустив `ps aux`.
